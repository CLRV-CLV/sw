# 敲敲当前实装范围

入口 `/messages`；首页“敲敲”快捷入口与原敲敲弹窗内“通讯录 / 新建私聊”链接均可进入。原弹窗的私聊REST/收件箱接口也接入同一后端。

## 已实装
- 本站真实账号通讯录，按账号或昵称查询，建立一对一私聊。
- SQLite持久化会话与消息，重启后保留；独立消息游标分页。
- 文本消息、引用、本人编辑、本人撤回；引用历史在读取时同步已撤回状态。
- 客户端标识去重，避免同次重试重复入库。
- 已读/未读、置顶、免打扰、隐藏会话及新消息重新出现。
- WebSocket按会话成员定向投递；每次发送事件重新核验会话有效性和封禁状态，匿名或无关用户不会收到私聊消息。
- 服务器核验每个消息/会话操作的成员身份，不能靠猜ID读取或编辑他人内容。

## 仍未完成（不能将上述称为完整微信/QQ替代）
- 群聊、频道、好友申请/分组/备注/黑名单。
- 文件、图片、语音、贴纸消息与对象存储。
- 语音/视频通话、WebRTC信令、TURN服务。
- 红包、转账、动态圈、会话内服务端搜索。
- 真实AI模型与角色记忆/工具调用。原UI存在的AI角色/群聊入口并不代表后端已实现。

当前通讯录是最近500个注册账号内搜索、最多展示50人，独立消息页最近会话最多展示50条；不是无限全量目录。原敲敲弹窗支持收件箱分页。免打扰是会话标记，本轮没有接入系统级推送服务，不能把它理解为已经完整实现浏览器/移动推送策略。

撤回是对展示内容的软撤回，不是加密销毁所有历史备份；本系统没有端到端加密。管理员应保护SQLite和备份访问权限。本轮后台没有增加私聊内容审阅入口。

验证：`node --test server/messenger.test.mjs server/messenger.integration.test.mjs`。覆盖权限隔离、幂等、引用/撤回、已读、偏好、重启持久化，真实WS验证只投递给成员、注销后旧连接不再收到私聊。
