# 管理后台

入口：`/admin` 自动布局、`/web/admin` 强制桌面、`/h5/admin` 强制手机。账号设置页也有链接。

## 当前可以管理什么
- 总览：用户、帖子、评论、会话数量。
- 帖子：查看（包括草稿）、编辑标题/源正文、公开/下架、永久删除。
- 评论：查看、编辑源正文、删除及级联删除子回复。
- 用户：授予/取消管理员权限、封禁/解封、注销全部会话。
- 设置：注册开关、普通用户**新建帖子**开关；这不是对既有草稿发布、编辑、评论的全面禁言开关。
- 审计：记录成功的管理员修改操作，按页查看；不记录密码、正文副本或授权令牌。

当前不是“任意管理一切”的最终版：没有文件/媒体管理、数据库备份恢复、任意SQL/终端、密码查看、第三方账号代登录、全部外部平台数据控制或尚未实现业务模块的管理。用户删除、密码重置和多级细粒度角色也尚未实现。此阶段用户管理采用封禁/会话撤销，不物理删除账号。

## 首位管理员

默认全新空库的第一个成功注册用户自动成为管理员（`AUTO_FIRST_ADMIN=1`）。账号插入、角色授予和初始化标记在同一SQLite事务中完成；并发注册不会产生多个首位管理员。标记一旦写入，即使之后清空用户，也不重新触发。演示作者不属于注册用户，不影响首位判定。

**首次部署应先限制公网访问，自己注册首个账号，再开放网站。**否则其他访问者也可能抢先注册成为管理员。

已有注册用户的旧数据库不会自动提升首个或下一个用户，避免更新时误提权。可通过部署配置恢复/指定管理员：

```sh
ADMIN_USERNAMES='实际已注册的用户名' node server/index.mjs
```

多个用户名用逗号分隔。生产中先确认用户名确实属于自己。没有预置管理员密码。`AUTO_FIRST_ADMIN=0` 可禁用自动首位授权。环境指定的管理员不能在后台降权/封禁，必须修改部署配置；管理员不能封禁或降权自己。

后台授予的角色/封禁持久化到同一个SQLite数据库。所有 `/v1/admin/*` 接口均检查本站会话、封禁状态和管理员角色；写请求沿用服务端的同源检查。禁止暴露password/salt/session token/OAuth secret。封禁会撤销现有会话，并拒绝重新登录。

权限检查不能只看前端。审计是本地数据库中的应用日志，不是防止拥有主机权限的人篡改的独立审计系统。永久删除不可撤销；操作前应自行备份数据库。

## 默认帖子的来源

`server/seed.mjs` 中的 `SEED_POSTS` / `SEED_COMMENTS` / `SEED_USERS` 是仓库自带的虚构演示内容。角色作者不是可登录的真实账号。这些帖子不是爬虫抓取、GitHub Discussions同步，也不是玩家真实投稿。`server/art.mjs` 用于本地演示SVG封面/头像；前端也使用仓库已有静态图片资产，不能把所有图像都声称为原创或官方授权。

启动后演示帖子/评论进入 `server/data/interknot.sqlite`（或 `DATA_DIR`）。本轮加入一次性初始化标记：管理员删除内容后，重启不再重新导入。旧库首次升级会进行一次种子补齐并写入标记，此后不再补回。种子文件不会覆盖已存在的相同ID。

全新部署不想要演示内容时：

```sh
SEED_DEMO=0 ADMIN_USERNAMES='实际已注册用户名' node server/index.mjs
```

`SEED_DEMO=0` 仅阻止首次导入，不自动删除已有数据。初始化标记写入后，改回环境变量也不会自动重新灌入种子。当前没有批量清空演示帖按钮，后台可逐条删除；不要通过删除整个数据库误删真实用户和帖子。

## 验证

```sh
node --test server/admin.test.mjs server/admin.integration.test.mjs
node server/test.mjs
npm run typecheck --prefix web
npm run test:unit --prefix web
npm run build:web --prefix server
```

本轮真实HTTP回归已验证：普通用户403、匿名401、封禁撤销会话且禁止登录、关闭注册、后台删帖后重启不补回、设置与审计持久化。浏览器已验证/web/admin及/h5/admin分别使用1440/430px内视口并呈现登录门禁，无横向溢出。管理员完整交互界面尚未进行浏览器端逐项点击回归；业务写接口由HTTP/模块测试覆盖。
