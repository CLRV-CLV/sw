# 驻站角色AI（New API兼容）

## 当前交付与边界

已实现服务端New API接入、Wiki目录发现/资料导入、详细角色档案生成与审核、服务器组装角色扮演系统提示词、指定/随机驻站作者生成草稿，以及敲敲内按用户/角色隔离的文字聊天。

**不是开箱即有真实模型回复，也不是已核实的全角色百科数据库。** 正式环境不再灌入旧的英文种子目录。管理员点击“萌娘百科全角色提示词流水线”后，从真实的 `分类:绝区零` 分页发现条目，并逐页校验正文确为登场角色/人物/NPC；组织、音乐、物品与邦布杂项不会直接当作角色导入。范围是该分类中有独立百科正文且通过校验的角色，不承诺百科未建页、未分类或资料不足的角色也能成功生成。分类/页面失败和截断会阻止结果报告 `allGenerated: true`。

**全角色导入失败的已知原因（已在本次修复）**：线上曾出现 25 个目录项只生成 9 份档案、16 项失败。三个独立原因：(1) 萌娘百科对突发匿名请求返回 `HTTP 403`，旧代码不重试、不节流，12 个角色在抓取阶段即失败，因此没有原文、也就无从生成；(2) 档案按 6500 tokens/60 秒生成，长档案在 60 秒处被切断或模型返回 JSON 不完整，3 个角色被结构校验拒绝且没有重试；(3) 1 次请求实际超过网关 60 秒未返回。修复后：源站请求带 `User-Agent`/`Accept`/`Referer` 等浏览器同源头，失败按指数退避重试（默认 4 次），同一进程内两次真实抓取至少间隔 900ms，命中验证码/拦截页立即判定为源站风控而不是“页面不存在”；档案生成放宽到 8000 tokens / 240 秒，并带一次“把它自己的校验错误回喂给模型”的修复重试。匿名 `api.php` 被拒后，同一进程内 30 分钟内不再重复探测，直接把后续角色走公开页面，减少触发风控的机会。连续 5 个角色都因源站失败时会自动暂停并报告剩余未处理项，避免把额度耗在必然失败的请求上。中断任务会立即中止正在进行的抓取或模型请求（长档案生成同样会中断），已完成角色保留。

已核实公开页面的真实标题是 `艾莲·乔`，不是猜测的 `绝区零:艾莲·乔`；图片来源包含 `storage.moegirl.org.cn` 的 `png!/fw/280` 形式。匿名 MediaWiki API 实测可能返回 `action-notallowed`，适配器在此情况下读取同站公开网页，校验页面结构与角色正文，不使用登录凭据、不绕过验证码、不回退 Fandom。若源站封禁、改版或缺页，任务明确失败。服务器需能访问萌娘百科公开页面和配置的 New API。

自动化测试使用明确的模拟模型/Wiki资料，覆盖公开页回退、杂项过滤、全角色流水线、一次性清理、任务中断及禁止晚到结果覆盖；另有真实本地HTTP和浏览器测试。**未接入部署者真实模型密钥，不能把模拟测试称为全部真实角色已抓取/已生成。**

### 本次一次性强制清理（升级前备份）

首次启动含 `moegirl-catalog-v1` 迁移的版本时，会按本次明确要求清除旧 `ai_roles` 全部角色记录（包括旧来源原文、审核和角色提示词），取消遗留排队/运行任务；不会重新填回旧种子。保留账号、资产、帖子、历史聊天和已完成日志。迁移标记入库，后续重启不重复清理新导入的角色。更新后先配置/检查 New API，再执行全角色流水线，完成后仍需人工核对、审核并启用。不要把旧 `AI_SEED_CATALOG=1` 测试开关带进正式环境。

这不是实时语音视频、动态圈、红包或转账实现，也没有将旧敲敲弹窗不同协议的AI会话接口伪装为已接通；旧弹窗新增入口跳到真实驻站文字聊天。

## 配置New API

在后台 **驻站AI / New API** 填写：

- Base URL：例如 `https://your-gateway.example` 或 `https://your-gateway.example/v1`。
- API Key：New API颁发的调用令牌，不是后台管理员登录口令。
- 模型名称：网关实际可用的模型ID。必须支持Chat Completions与`response_format: {type: "json_object"}`，且上下文能容纳较详细的Wiki资料。
- 勾选启用并保存。

实际请求为 `POST <网关根路径>/v1/chat/completions`，使用`Authorization: Bearer ...`；不自动跳转到另一个主机，不把上游原始报错返回用户，不把密钥放入提示词。默认要求HTTPS；确需可信内网/本机HTTP网关时，由部署者设置`AI_ALLOW_HTTP=1`并重启。不要对不可信公网HTTP发送密钥。

也可在仓库根`.env`设置（后台保存过的值优先；不要在聊天中提供密钥）：

```dotenv
AI_ENABLED=1
AI_BASE_URL=https://your-gateway.example/v1
AI_API_KEY=填写真实令牌
AI_MODEL=填写真实模型ID
AI_ALLOW_HTTP=0
AI_DAILY_CHAT_LIMIT=500
# 可选：萌娘百科单个页面的最多尝试次数（默认4，范围1–10）
AI_WIKI_ATTEMPTS=4
# 可选：两次真实萌娘百科请求之间的最小间隔毫秒数（默认900，范围0–10000）
AI_WIKI_MIN_INTERVAL_MS=900
```

不要把上述值写入前端运行时配置、浏览器代码或Git。密钥更换需在后台直接填写新值，留空表示保留。环境变量密钥需在部署环境清除，不能通过后台假装已清除。

## Wiki和详细档案

1. 推荐点击“发现并生成未完成角色”，确认模型费用后依次发现、抓取、概括全部发现的有效角色。后台展示目录数、已完整跳过、待处理、已导入、已生成、失败数，并把失败按原因分组列出角色名；完整结果以实际成功数为准。停止不会撤销已完成的角色。**再次运行时已生成的角色自动跳过、不会重复计费**；“只重试未完成角色”按钮只重试未完成项、不重新抓目录，适合在源站风控或网关超时后继续。出现 `stoppedEarly` 表示源站连续拒绝并已自动暂停，稍后重试即可。
2. 目录有两个来源：`分类:绝区零` 分页与条目页脚“登场角色”导航模板（`Template:绝区零`），只有逐页核对正文确认是登场角色/人物/NPC 后才算导入成功；目录诊断（分类是否可读、导航模板是否可读、检查页数、跳过杂项数、单页失败数）随任务结果返回，不会把“抓到 0 个”说成成功。也可只发现目录，再使用单角色或批量导入/生成。批量单任务入队最多100项，不等于全角色只有100项；整站流水线在一个任务中逐角色处理。发现有分页和2000个目录项上限，达到上限明确报告截断。
3. 只导入萌娘百科角色主页面。去除脚本、样式、导航模板等无关内容，保存真实来源URL、修订号（可获取时）、时间、正文哈希和许可链接。原文800–90000字符；不足时失败，不编造档案。
4. 网络受限时可手动粘贴对应萌娘百科主页面原文，明确标记“管理员提供，未由服务器抓取验证”；不是伪造抓取成功。旧 Lore / Voice-Overs / DMs 子页选项已移除。
5. 配好模型后生成8字段详细档案：身份、外观、性格、说话方式、经历、关系、日常、知识边界；结构和长度校验至少1600字符（每字段40–4000字），未知须标记未知，不得为了凑长度编造。原文只截取开头与结尾共约2.4万字符送模型，避免超长原文挤掉输出。校验失败时会把模型自己写出的问题回喂一次要求重写；仍不合格则明确失败，不会静默丢弃角色。
6. 核对原文与引用、必要时编辑档案；只有先审核通过再启用，角色才能聊天或写作。编辑/重新导入会撤销旧审核。

系统提示词由服务器把统一边界策略与已审核档案组合；客户端不能提交自定义system/developer消息、替换模型、注入另一角色的历史或传入任意聊天上下文。模型没有工具调用、管理命令、转账或网页访问权限。

来源：[萌娘百科《绝区零》分类](https://zh.moegirl.org.cn/Category:绝区零)、[艾莲·乔](https://zh.moegirl.org.cn/艾莲·乔)。具体引用保存在各角色档案。萌娘百科文字默认 **CC BY-NC-SA 4.0（署名、非商业性使用、相同方式共享）**，必须保留署名/来源并核查衍生提示词的许可义务；此接入不授予商业使用许可，图片另按权利人许可处理。不是官方合作或剧情认证。

## 驻站写作

后台可以指定启用角色，或从已审核启用的角色中随机选择，再提交**角色相关**命令。

生成结果做输入/输出话题审查、JSON/长度检查，禁止HTML及外链。成功后以`ai:<角色ID>`作为作者保存真实帖子草稿，标题/正文显式标记AI同人，**不自动发布**。到后台帖子栏目审核、编辑并公开后会出现在普通推送。管理员发文命令也不能绕过角色范围审查。

AI作者不创建可登录的人类账号，也不占据“首位注册用户自动管理员”位置。其个人空间/公开帖子作者带AI标识。

## 敲敲聊天

首页敲敲入口或 `/web/messages?tab=ai`（手机 `/h5/messages?tab=ai`）进入“驻站角色AI”。同一用户每个角色一条持久化对话，历史可分页。对话数据按账号/角色隔离；管理员任务列表不展示用户聊天任务或内容。

仅允许角色本人及与其直接有关的经历、关系、新艾利都日常。角色扮演不是通用问答入口；现实编程、新闻、医疗/法律/金融等无关请求被拒绝。服务端先检查明显套取请求，再让模型做主题判定，生成后再审查输出。不确定/无效审查结果不放行。

每账号每分钟5次、滚动24小时50次聊天任务；全站滚动24小时默认500次，可用`AI_DAILY_CHAT_LIMIT`调整（1–10000）。失败/拒绝也占额度，重复客户端标识不重复计入。同账号同角色同时只处理一个回复。正常成功一轮通常需要3次模型调用（话题审查、生成、输出审查）。

当前部署应使用单个Node进程（不要PM2 cluster多实例共享同一SQLite）；服务端单队列控制并发费用，聊天优先于尚未开始的批量资料任务，但不会中断已经运行的模型请求。任务状态持久化；服务重启后未完成任务标记失败，**不自动重放付费调用**。账号封禁、管理员权限撤销或角色档案版本改变会阻止过期任务输出落库。

## 防套话 / 防逆向的准确含义

- 普通客户端拿不到API Key、内部策略提示词或完整后台档案；Key不参与模型上下文，也不写入审计日志。
- 后台Key用AES-256-GCM加密存储；默认密钥文件为`DATA_DIR/.ai-config-key`（0600），也可固定`AI_CONFIG_SECRET`。
- 用户输入、Wiki原文、历史对话均不授予管理权限，模型无法执行站点操作。
- 规则过滤、独立话题审查与输出审查叠加；接口拒绝客户端传入system/历史消息；输出不作为命令执行。
- **不能保证大模型绝对不被越狱、套出角色风格或复述策略。**审查模型也可能判断错误。公开Git仓库中的通用提示词模板本身可被阅读，不能靠隐藏模板当作安全边界。公开Wiki人物事实更不是秘密。
- 需要对真实部署选用的模型持续做越狱回归与内容质量抽查。现有测试不是所有攻击的证明，也不是模型质量认证。

## 连接测试、重复项与删除

- 保存 New API 配置后，点击“测试已保存配置的连接”。测试会真实调用模型、消耗少量额度，同时验证认证、模型调用和 JSON 输出；不是只检查 URL 能否打开。任务状态每 2.5 秒刷新，显示排队、处理中、成功或失败及结果。
- 目录按已知中英文角色别名与规范化 Wiki 标题去重；“清理不同语言的重复目录项”清理未使用的重复项。已启用、已审核、有历史聊天/文章的重复项保留并报告，避免自动误删。未知 NPC 的跨语言别名仍需人工确认，不保证自动识别所有翻译。
- “清空Wiki资料”清除该角色全部原文、来源与档案，并停用、撤销审核；后续可以重新导入。当前不是逐个来源删除。
- “删除此角色”保留删除标记，重启与自动目录发现不会将它重新加入；保留已有文章、聊天和 AI 作者归属。进行中的资料任务通过角色版本校验，不会在删除/清空后重新写回旧资料。
- 同一管理员重复点击同角色导入/档案生成时，复用现有排队或运行任务，减少重复抓取与额度消耗。

## 自由管理、中文名过滤与头像

所有当前目录项（种子及新增角色）使用同一套增删改管理：可新增、改显示名/Wiki标题、查看原文、替换粘贴原文、编辑档案、清空资料、删除角色。抓取来源仅限萌娘百科，并不是任意网站 URL 抓取器。修改标题或原文会撤销旧审核，需重新核对。

“发现与批量导入时跳过没有中文名的角色”默认关闭；已知英文 Wiki 标题先匹配中文种子名，无中文名的新条目跳过。关闭可处理外语名称。此项不删除现有角色，也不限制单角色管理。

导入资料时会从主页面信息框识别角色图，自动设为头像（远程 Wiki CDN 图片地址，非本地镜像；受原站可用性影响）。可单独/批量更新 Wiki 头像，独立更新不重置档案与审核。手动上传/设置的头像不会被自动导入覆盖；恢复 Wiki 自动模式后，再点击获取头像。图片仍属于原权利方，保留 Wiki 来源入口。

## New API 兼容与诊断

Base URL 支持根地址、`/v1` 和完整 `/v1/chat/completions` 地址，完整接口路径不会再次拼接。不兼容 `response_format` 的模型可关闭“强制JSON模式”；仍要求有效 JSON 内容并校验字段，支持剥除模型返回的 JSON 代码围栏，不会因此放宽角色审核与防泄漏策略。

连接测试可在服务尚未启用时运行（不会自动启用角色）。HTTP401/403/404/429、参数不兼容、DNS、部分TLS错误和超时会分别报告，不显示原始网关响应或令牌。测试成功不代表长档案生成、所有话题或每个模型参数都可用。

本机网关如果使用 `http://127.0.0.1:端口`，部署者需要在 `.env` 设置 `AI_ALLOW_HTTP=1` 并重启后才可保存 HTTP 地址；默认仍要求 HTTPS。不关闭 TLS 校验，也不自动复制另一项目的密钥或代理配置。实际线上故障请对照测试结果与网关日志，不能仅凭“同机别的项目可用”判断全部链路相同。

“展开全部角色管理”支持中文名/英文标题搜索，勾选最多100项，批量导入Wiki、更新头像或删除。显式勾选的角色不受中文名自动过滤限制；批量头像任务仍尊重手动头像保护。批量删除先验证全部ID并使用事务，避免部分ID无效导致只删了一半。


## 任务与日志管理

- 排队/运行的非聊天管理任务可点击“中断任务”，中止请求和后续批处理；已完成部分保留。取消状态不会被晚到请求改写成成功。
- 已结束的任务可单条删除日志，也可清空已结束日志；运行中的日志必须先中断才能删除。清理日志不删除角色、帖子或用户私聊历史。
- 删除角色或清空原文会使相关在途资料请求失效；不会被晚到结果恢复。旧千条目录仍可全选、反选、筛选并批量删除。
