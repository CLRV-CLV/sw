# 驻站角色AI（New API兼容）

## 当前交付与边界

已实现服务端New API接入、Wiki目录发现/资料导入、详细角色档案生成与审核、服务器组装角色扮演系统提示词、指定/随机驻站作者生成草稿，以及敲敲内按用户/角色隔离的文字聊天。

**不是开箱即有真实模型回复，也不是已核实的全角色百科数据库。** 仓库种子目录含61个代理人条目、铃/哲/Fairy/伊埃斯、4个已公布角色条目；目录基于2026-10-27 Wiki快照，后续可发现Wiki Agents/NPCs分类、补充新角色和修正页面标题。目录条目不等于已抓取或已审核的档案。未导入、未生成、未审核或未启用的角色不会上线。

本次自动化测试使用明确的模拟模型/Wiki资料，验证HTTP协议、权限、状态机、输出阻断、幂等和前端流程。**未接入部署者的真实New API密钥，也没有声称全角色真实Wiki原文/模型质量已实测。** 当前沙箱到Wiki API的直连受网络限制；部署服务器需能够访问Wiki API和配置的New API。Wiki防护/503/缺页不会被当作成功。

这不是实时语音视频、动态圈、红包或转账实现，也没有将旧敲敲弹窗不同协议的AI会话接口伪装为已接通；旧弹窗新增入口跳到真实驻站文字聊天。

## 配置New API

在后台 **驻站AI / New API** 填写：

- Base URL：例如 `https://your-gateway.example` 或 `https://your-gateway.example/v1`。
- API Key：New API颁发的调用令牌，不是后台管理员登录口令。
- 模型名称：网关实际可用的模型ID。必须支持Chat Completions与`response_format: {type: "json_object"}`，且上下文能容纳较详细的Wiki资料。
- 勾选启用并保存。

实际请求为 `POST <网关根路径>/v1/chat/completions`，使用`Authorization: Bearer ...`；不自动跳转到另一个主机，不把上游原始报错返回用户，不把密钥放入提示词。默认要求HTTPS；确需可信内网/本机HTTP网关时，由部署者设置`AI_ALLOW_HTTP=1`并重启。不要对不可信公网HTTP发送密钥。

也可在仓库根`.env`设置（后台保存过的值优先；不要在聊天中提供密钥）：

```dotenv
AI_ENABLED=1
AI_BASE_URL=https://your-gateway.example/v1
AI_API_KEY=填写真实令牌
AI_MODEL=填写真实模型ID
AI_ALLOW_HTTP=0
AI_DAILY_CHAT_LIMIT=500
```

不要把上述值写入前端运行时配置、浏览器代码或Git。密钥更换需在后台直接填写新值，留空表示保留。环境变量密钥需在部署环境清除，不能通过后台假装已清除。

## Wiki和详细档案

1. 可先点击“从Wiki发现角色 / NPC目录”；这是固定Wiki站点的分类发现，不接受任意抓取URL。分类/网络异常会显示失败；分类索引不完整或达到上限时，不能将结果宣称为所有NPC均已收录。
2. 点击“批量导入全部角色Wiki”或单角色导入。批量跳过已导入项，最多填满100个队列位，超出部分需下一批。单角色重新导入成功会清除旧档案审核并停用角色；抓取失败保留旧档案。
3. Wiki网络受限时可手动粘贴对应页面原文（800–90000字符，可带修订号），明确标记为“管理员提供，未由服务器抓取验证”，不是伪造抓取成功；仍需生成/核对/审核。
4. 自动导入角色主页面、Lore、Voice-Overs、DMs（缺失页跳过，资料不足则失败），保存来源URL、修订号、时间、内容哈希。去除脚本、样式和HTML标签，资料仅作模型参考。
5. 配好模型后，单角色或批量生成详细档案。**批量会消耗较多模型额度，操作前需要确认。**
6. 档案由8个字段组成：身份、外观、性格、说话方式、经历、关系、日常、知识边界；JSON结构和长度有检查，要求总计至少1600字符。未知必须写明未知，不要求模型为了凑长度编造设定。
7. 查看Wiki原文与引用并人工核对，可编辑JSON。编辑后会重置审核和启用状态。只有先“审核通过”、再“启用角色”才能聊天或写作。源页面写错/重命名时可以修正Wiki标题，再重新导入。

系统提示词由服务器把统一边界策略与已审核档案组合；客户端不能提交自定义system/developer消息、替换模型、注入另一角色的历史或传入任意聊天上下文。模型没有工具调用、管理命令、转账或网页访问权限。

来源：[Agents](https://zenless-zone-zero.fandom.com/wiki/Agent)、[NPCs分类](https://zenless-zone-zero.fandom.com/wiki/Category:NPCs)。每个角色的具体引用保存在其档案。Wiki内容遵守来源站许可及署名要求；参见[Fandom许可说明](https://www.fandom.com/licensing)。这不是官方合作或官方剧情认证。

## 驻站写作

后台可以指定启用角色，或从已审核启用的角色中随机选择，再提交**角色相关**命令。

生成结果做输入/输出话题审查、JSON/长度检查，禁止HTML及外链。成功后以`ai:<角色ID>`作为作者保存真实帖子草稿，标题/正文显式标记AI同人，**不自动发布**。到后台帖子栏目审核、编辑并公开后会出现在普通推送。管理员发文命令也不能绕过角色范围审查。

AI作者不创建可登录的人类账号，也不占据“首位注册用户自动管理员”位置。其个人空间/公开帖子作者带AI标识。

## 敲敲聊天

首页敲敲入口或 `/web/messages?tab=ai`（手机 `/h5/messages?tab=ai`）进入“驻站角色AI”。同一用户每个角色一条持久化对话，历史可分页。对话数据按账号/角色隔离；管理员任务列表不展示用户聊天任务或内容。

仅允许角色本人及与其直接有关的经历、关系、新艾利都日常。角色扮演不是通用问答入口；现实编程、新闻、医疗/法律/金融等无关请求被拒绝。服务端先检查明显套取请求，再让模型做主题判定，生成后再审查输出。不确定/无效审查结果不放行。

每账号每分钟5次、滚动24小时50次聊天任务；全站滚动24小时默认500次，可用`AI_DAILY_CHAT_LIMIT`调整（1–10000）。失败/拒绝也占额度，重复客户端标识不重复计入。同账号同角色同时只处理一个回复。正常成功一轮通常需要3次模型调用（话题审查、生成、输出审查）。

当前部署应使用单个Node进程（不要PM2 cluster多实例共享同一SQLite）；服务端单队列控制并发费用，聊天优先于尚未开始的批量资料任务，但不会中断已经运行的模型请求。任务状态持久化；服务重启后未完成任务标记失败，**不自动重放付费调用**。账号封禁、管理员权限撤销或角色档案版本改变会阻止过期任务输出落库。

## 防套话 / 防逆向的准确含义

- 普通客户端拿不到API Key、内部策略提示词或完整后台档案；Key不参与模型上下文，也不写入审计日志。
- 后台Key用AES-256-GCM加密存储；默认密钥文件为`DATA_DIR/.ai-config-key`（0600），也可固定`AI_CONFIG_SECRET`。
- 用户输入、Wiki原文、历史对话均不授予管理权限，模型无法执行站点操作。
- 规则过滤、独立话题审查与输出审查叠加；接口拒绝客户端传入system/历史消息；输出不作为命令执行。
- **不能保证大模型绝对不被越狱、套出角色风格或复述策略。**审查模型也可能判断错误。公开Git仓库中的通用提示词模板本身可被阅读，不能靠隐藏模板当作安全边界。公开Wiki人物事实更不是秘密。
- 需要对真实部署选用的模型持续做越狱回归与内容质量抽查。现有测试不是所有攻击的证明，也不是模型质量认证。

## 连接测试、重复项与删除

- 保存 New API 配置后，点击“测试已保存配置的连接”。测试会真实调用模型、消耗少量额度，同时验证认证、模型调用和 JSON 输出；不是只检查 URL 能否打开。任务状态每 2.5 秒刷新，显示排队、处理中、成功或失败及结果。
- 目录按已知中英文角色别名与规范化 Wiki 标题去重；“清理不同语言的重复目录项”清理未使用的重复项。已启用、已审核、有历史聊天/文章的重复项保留并报告，避免自动误删。未知 NPC 的跨语言别名仍需人工确认，不保证自动识别所有翻译。
- “清空Wiki资料”清除该角色全部原文、来源与档案，并停用、撤销审核；后续可以重新导入。当前不是逐个来源删除。
- “删除此角色”保留删除标记，重启与自动目录发现不会将它重新加入；保留已有文章、聊天和 AI 作者归属。进行中的资料任务通过角色版本校验，不会在删除/清空后重新写回旧资料。
- 同一管理员重复点击同角色导入/档案生成时，复用现有排队或运行任务，减少重复抓取与额度消耗。

## 自由管理、中文名过滤与头像

所有当前目录项（种子及新增角色）使用同一套增删改管理：可新增、改显示名/Wiki标题、查看原文、替换粘贴原文、编辑档案、清空资料、删除角色。抓取来源仍限定本项目支持的 ZZZ Fandom Wiki，并不是任意网站 URL 抓取器。修改标题或原文会撤销旧审核，需重新核对。

“发现与批量导入时跳过没有中文名的角色”默认开启；已知英文 Wiki 标题先匹配中文种子名，无中文名的新条目跳过。关闭可处理外语名称。此项不删除现有角色，也不限制单角色管理。

导入资料时会从主页面信息框识别角色图，自动设为头像（远程 Wiki CDN 图片地址，非本地镜像；受原站可用性影响）。可单独/批量更新 Wiki 头像，独立更新不重置档案与审核。手动上传/设置的头像不会被自动导入覆盖；恢复 Wiki 自动模式后，再点击获取头像。图片仍属于原权利方，保留 Wiki 来源入口。

## New API 兼容与诊断

Base URL 支持根地址、`/v1` 和完整 `/v1/chat/completions` 地址，完整接口路径不会再次拼接。不兼容 `response_format` 的模型可关闭“强制JSON模式”；仍要求有效 JSON 内容并校验字段，支持剥除模型返回的 JSON 代码围栏，不会因此放宽角色审核与防泄漏策略。

连接测试可在服务尚未启用时运行（不会自动启用角色）。HTTP401/403/404/429、参数不兼容、DNS、部分TLS错误和超时会分别报告，不显示原始网关响应或令牌。测试成功不代表长档案生成、所有话题或每个模型参数都可用。

本机网关如果使用 `http://127.0.0.1:端口`，部署者需要在 `.env` 设置 `AI_ALLOW_HTTP=1` 并重启后才可保存 HTTP 地址；默认仍要求 HTTPS。不关闭 TLS 校验，也不自动复制另一项目的密钥或代理配置。实际线上故障请对照测试结果与网关日志，不能仅凭“同机别的项目可用”判断全部链路相同。

“展开全部角色管理”支持中文名/英文标题搜索，勾选最多100项，批量导入Wiki、更新头像或删除。显式勾选的角色不受中文名自动过滤限制；批量头像任务仍尊重手动头像保护。批量删除先验证全部ID并使用事务，避免部分ID无效导致只删了一半。
