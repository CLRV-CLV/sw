# 发帖格式兼容范围

目标：持续扩展 Markdown 与富文本兼容，而非只支持纯文本。不存在覆盖所有私有扩展的
单一 Markdown 标准；目前以 CommonMark + 常用 GFM/论坛扩展为可测试基线。

## 已实现

- 桌面和手机共用 Markdown/HTML 源码、富文本编辑、效果预览三种模式。
- Markdown：标题、粗斜体、引用、嵌套列表、分隔线、链接、图片链接、表格、删除线。
- 扩展：只读任务列表、脚注、定义列表、`==高亮==`、`H~2~O`、`x^2^`。
- 代码：围栏代码块、已知语言语法高亮；未知语言转义显示，不执行。
- 公式：`$...$` / `$$...$$`，KaTeX 解析为原生 MathML；禁用可信命令。
- 富文本工具栏：粗斜体、下划线、删除线、列表、对齐、标题、引用、代码、链接、
  图片链接、简单表格、字色、清除格式、撤销重做（取决于浏览器编辑能力）。
- 粘贴 HTML 经净化；保留安全表格/段落/文本格式。效果预览、帖子详情和弹层使用
  同一套渲染过滤规则。

## 数据与切换行为

后端保存正文源码，不运行用户内容。富文本编辑时输出净化 HTML，仍沿用正文保存、
草稿及发布接口。Markdown → 富文本仅预览转换，不立即改写源码；一旦在富文本中
编辑，将以 HTML 保存。切回源码看到的是 HTML，不承诺无损还原原 Markdown 排版。
不会为了“转回 Markdown”静默丢弃表格、字色等富文本信息。

## 安全边界与未实现

- 不允许 script、iframe、form、SVG、内联事件或 javascript: 链接。
- 用户 CSS 仅接受受限的文本呈现属性；不能注入定位、外部 URL、遮罩或任意站内类名。
- 任务列表 input 强制为 disabled checkbox，不接受可交互表单。
- 尚不支持 Mermaid、PlantUML、所有平台的自定义 Markdown 插件、任意视频/音频嵌入、
  Word/Excel 逐像素无损导入、复杂表格合并工具、附件上传或多人协作编辑。
- 图片链接可渲染，不等同已完成本站图片上传。
- API 返回用户源码；任何新增消费端都必须渲染前过滤，不能直接注入未经处理的 HTML。

## 本轮验证

9项正文格式/安全测试 + 7项图片路径测试通过，TypeScript检查与静态构建通过。
浏览器实测：登录后打开编辑器、Markdown任务/公式/表格预览、富文本编辑后切换源码、
手机预览、发布并重新打开帖子，表格、公式和追加文字保留；无未捕获页面异常。
不宣称已支持“所有Markdown方言”和“所有富文本格式”。
